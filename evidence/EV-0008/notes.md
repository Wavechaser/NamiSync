## Coherent follow-up proposal (discussion only)

1. **First candidate: row-type-aware Inventory payload.** Keep current row
   interaction facts and full checksum; keep complete rollup on every container;
   omit entire 14-field rollup on noncontainers. Remove `has_baseline` and
   `row_kind`, and remove window `row_id` by using already-required nullable
   presence for ledger-subject classification. Expected largest reduction in
   leaf-heavy windows is repeated rollup keys/scalars, not checksum contents.
   Actual bytes depend on leaf/container mix and numeric widths; defer numbers
   to byte-attribution receipts. No server rollup/projection change is needed.
2. **Independent Plan candidate:** remove four unused tree geometry wire
   fields; conditionally omit three container-only count fields on noncontainers.
   Preserve grid keyboard/highlight behavior and existing server selection truth.
3. **Later, measured only if necessary:** defer most container facet counts to a
   revised revisioned exact-detail/snapshot contract, retaining table size flags
   and immediate recursive-action eligibility. This crosses both detail shape
   and loading/failure UX; current detail cannot replace those facts. Similarly,
   transmitting only checksum prefix plus fetching full value on hover is a UX
   and I/O redesign, not behavior-preserving compaction. Neither is proposed as
   an initial migration.

Avoid array DTOs, shortened keys and browser reconstruction of domain rollups.
They add schema complexity before proving that redundant semantic fields are
insufficient. An approved implementation needs an atomic producer/validator/
consumer migration, matching PRESENTATION/BRIDGE ownership documentation, and
affected probes/finite bound derivation updates. Current measurement authority
does not authorize that migration.
